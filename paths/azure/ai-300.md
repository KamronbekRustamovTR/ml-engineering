# Azure path: AI-300, Machine Learning Operations Engineer Associate

**Who this is for / prerequisites.** This path is for a senior backend engineer who has finished the [ML core](../../core-ml-engineering.md) and the [AI core](https://github.com/KamronbekRustamovTR/ai-engineering/blob/main/core-llm-app-engineering.md) and wants the Microsoft MLOps certification. It is a strict delta. Concepts such as experiment tracking, pipelines, drift, rollout strategies, evals, RAG tuning and fine-tuning are already learned and are only cross-referenced here (M and C IDs). What this file teaches is Azure Machine Learning (AzureML), Foundry fine-tuning, the AI-300 exam framing and the labs. Shared Azure services live in the ai-engineering repo's [ai-103.md](https://github.com/KamronbekRustamovTR/ai-engineering/blob/main/paths/azure/ai-103.md): Entra ID, managed identity, Foundry RBAC, private networking, Foundry resources/projects, deployment types, PTU, App Insights/KQL, Bicep/azd basics and GitHub Actions OIDC login in **AZ-AI103.1**; the Foundry model catalog in **AZ-AI103.2**; Foundry evaluators, tracing and continuous monitoring in **AZ-AI103.4**; AI Search in **AZ-AI103.6**. **If you took the Azure AI path, you already have these. Otherwise do just these modules from it: AZ-AI103.1 (8 h) before AZ-AI300.1; AZ-AI103.2 (4 h), AZ-AI103.4 (4 h) and AZ-AI103.6 (6 h) before AZ-AI300.8. That is 22 h.** Skip AZ-AI103.0 (AI-103 exam framing), and in AZ-AI103.6 index your C7.2 chunks instead of AZ-AI103.5 output. All exercises are in Python (`azure-ai-ml` SDK v2, `azure-identity`, `mlflow`). Bicep, YAML and `az ml` CLI appear only as configuration, because the exam tests them.

## Exam-day tactics and first-hand traps

**Tactics.**
- Learn is open in a split screen, but first-hand AI-103 reports say pages are slow to load ([Sameeraman, unconfirmed][sam]). Use it only for exact CLI flags or YAML keys, never to learn a concept.
- Answer case studies with the requirement in front of you; the right answer is usually the least-privilege or least-ops option (a heuristic, not a Microsoft rule).
- Don't take a break mid-section, because earlier questions lock ([exam experience][dur]).

**First-hand.** The only AI-300 report (passed August 2026) says the exam "feels like a mix of AZ-400, AI-200 and AI-103", took about 30 h for someone who already held those certs, and leans on MLflow, versioning, deployment strategies, drift, prompt versioning, RAG optimisation and fine-tuning decisions. The difficulty is telling similar options apart by requirement ([ghost_choisuke, single report, unconfirmed][ghost]). The same page sells an unofficial paid question bank; ignore it.

**Doc-derived traps** (all from the cited docs, as of 2026-10-31):
- Mirroring: ≤50%, one shadow deployment, never returned to clients. Requests that name a deployment aren't mirrored, and Kubernetes endpoints can't mirror ([rollout][rollout]).
- Managed VNet modes can't be relaxed after you set them. FQDN rules add Azure Firewall cost. Model monitoring doesn't work under `allow_only_approved_outbound` ([mvnet][mvnet], [mon][mon]).
- Reference data: use training data for data drift and quality, validation data for prediction drift. The performance signals need ground truth ([mon][mon]).
- Batch endpoints: you collect the inference data yourself for monitoring ([mon][mon]). Compute is provisioned when a job starts and deallocated when it ends, so you pay only for compute while jobs run ([batch][batch]).
- An archived model is hidden, not deleted, and still deployable. Only `description` and `tags` are mutable ([models][models]).
- The RAI dashboard covers only tabular scikit-learn MLflow models and doesn't support AutoML MLflow models ([rai][rai]).
- AzureML's "Generation safety and quality" signal is a preview that monitors prompt flow deployments, and prompt flow retires on 2027-04-20 ([genmon][genmon], [prompt flow migration][pfmig]). GenAI monitoring belongs to Foundry (.8).
- Foundry RBAC role names changed (→ AZ-AI103.1). Workspaces created after 2024-11-19 give their managed identity the Azure AI Administrator role, not Contributor ([ftsft][ftsft], [roles][roles]).
- Fine-tuning has separate training types and deployment types. Developer deployments last 24 h and are for evaluation only ([ftover][ftover]).
